# 시간 경계 무결성

## 저장 계약

- 실제 시각은 `messages.sent_at timestamptz`에 저장한다.
- Supabase DB timezone은 UTC를 유지한다.
- 기록 날짜는 `messages.day date`에 별도로 저장한다.
- 운영 설정은 `Asia/Seoul`, `day_boundary_hour = 4`다.
- KST 04:00 이상부터 해당 달력 날짜에 속하며 04:00 전은 전날에 속한다.

| KST 시각 | UTC 시각 | 저장 day |
|---|---|---|
| 2026-09-24 03:59:59 | 2026-09-23 18:59:59Z | 2026-09-23 |
| 2026-09-24 04:00:00 | 2026-09-23 19:00:00Z | 2026-09-24 |

## 이중 검증

애플리케이션은 Telegram Unix timestamp를 UTC `Date`로 변환하고 `getLocalDay()`로 day를 계산한다. DB는 `messages_enforce_local_day` trigger에서 `settings.timezone`과 `day_boundary_hour`를 읽어 `local_day(sent_at, ...)` 결과를 다시 계산한다.

두 결과가 다르면 SQLSTATE `23514`로 insert 또는 `sent_at`/`day` update를 거부한다. 과거 행은 설정 변경 시 자동 재분류하지 않으며, 메시지를 받을 당시 계산한 기록 날짜를 불변 근거로 유지한다.

## 접근 통제

- trigger 함수는 `SECURITY INVOKER`다.
- `search_path`는 빈 값으로 고정하고 모든 객체를 schema-qualified 이름으로 참조한다.
- `public`, `anon`, `authenticated`, `service_role`의 직접 `EXECUTE` 권한을 모두 회수한다.
- 함수는 Data API RPC로 호출하지 않고 message write trigger로만 실행한다.

## 검증 결과

- 앱 경계 테스트와 migration 계약 테스트를 포함해 자동 테스트 91개 통과
- 운영 DB에서 경계 직전/직후 정상 저장과 UTC round-trip 확인
- 잘못된 day insert와 update 거부 확인
- 검증 트랜잭션 rollback 후 테스트 행 0건 확인
- Security Advisor 새 ERROR/WARN 없음

D01~D02는 검증된 `messages.day`를 기준으로 [[21 야간 입력 Snapshot]]을 생성한다. 다음 단계 D03~D04는 이 snapshot을 Groq Structured Output에 전달하고 반환된 source ID와 enum/range를 로컬에서 검증한다.
