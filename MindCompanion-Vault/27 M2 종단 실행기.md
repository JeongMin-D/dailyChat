# M2 종단 실행기

## 목적

D01~D10에서 개별 검증한 야간 처리 단계를 하나의 실행 경로로 연결한다. 실행기는 원문이나 일기 본문을 로그에 남기지 않고 식별자와 상태만 반환한다.

## 실행 순서

1. KST 04:00 경계 기준 마지막으로 완전히 닫힌 날짜를 선택한다.
2. 해당 날짜의 user message snapshot과 SHA-256 input hash를 만든다.
3. `day + pipeline version + input hash`로 job을 준비한다.
4. 신규·재개·stale running job을 원자적으로 claim한다.
5. Groq strict structured output을 추출하고 로컬 계약을 검증한다.
6. 파생 데이터와 근거, 일기, safety를 한 트랜잭션으로 저장한다.
7. safety level에 맞는 reference-only outbox를 등록한다.
8. Telegram 메시지를 전송하고 provider message ID를 기록한다.

## 멱등성과 중단 복구

- 메시지가 없으면 job을 생성하지 않고 skip한다.
- 같은 입력의 성공 job은 추출과 저장을 반복하지 않는다.
- 기존 outbox를 다시 조회해 pending·retryable 알림만 전송한다.
- 실행 경쟁에서 claim을 얻지 못하면 LLM 호출 전에 종료한다.
- 5분 이상 갱신되지 않은 running job은 DB stale claim 조건이 허용할 때만 다시 처리한다.
- 저장 뒤 알림 단계에서 중단되면 다음 동일 입력 실행이 기존 diary/outbox를 사용해 전송을 재개한다.

## 실행 명령

```powershell
npm run run:nightly
```

`NIGHTLY_TARGET_DAY=YYYY-MM-DD`를 설정하면 특정 날짜를 수동 재생한다. 값을 비우면 실행 시점에 target day를 계산한다. 이 명령은 운영 DB를 변경하고 실제 Telegram 메시지를 전송하므로 scheduler 연결과 첫 운영 실행은 별도 검증 단계에서 수행한다.

## 검증

- 신규 실행의 단계 순서 확인
- 성공 입력 no-op에서 extract/save 미호출 확인
- 빈 입력 무외부호출 확인
- 동시 claim 패배 시 추출 미호출 확인
- stale running 재개 확인
- terminal failed 재실행 차단 확인
- 실제 Supabase Data API에서 존재하지 않는 UUID claim 결과 `false` 확인
- lint·typecheck·자동 테스트 161개 통과
