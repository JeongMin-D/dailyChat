# 구조화 추출과 근거 검증

## 처리 흐름

1. D01~D02 canonical snapshot을 입력으로 받는다.
2. 메시지가 0건이면 Groq를 호출하지 않고 `no_user_messages`로 끝낸다.
3. `nightly-v1` system prompt와 strict JSON Schema로 `openai/gpt-oss-120b`를 호출한다.
4. JSON을 파싱하고 Ajv shape와 로컬 의미 규칙을 검증한다.
5. 첫 실패는 검증 경로만 전달해 한 번 교정하고, 두 번째 실패는 저장하지 않는다.

## 신뢰 경계

- snapshot JSON과 `messages.content`는 모두 신뢰하지 않는 자료다.
- 원문 안의 역할 변경, 비밀 출력, 형식 변경 지시는 실행하지 않는다.
- source UUID는 입력 snapshot의 ID 집합과 대조한다.
- correction에는 `instancePath`, `keyword`, 일반화된 `message`만 포함한다.
- 원문, 잘못된 모델 출력, source UUID params, API 오류 본문은 로그에 남기지 않는다.

## 로컬 의미 검증

- 출력 day와 snapshot day 일치
- source ID가 snapshot 안에 존재
- eventRef 유일성과 diary event 참조 존재
- 배열 값 중복 금지
- safety none/concern/urgent와 사유·근거 일관성
- JSON Schema enum, 범위, UUID, nullable, 필수 필드

## 실패 코드

| 코드 | 의미 |
|---|---|
| `INVALID_INPUT_SNAPSHOT` | 지원하지 않는 snapshot 또는 잘못된 입력 |
| `GROQ_EXTRACTION_REQUEST_FAILED` | Groq HTTP 실패 |
| `GROQ_EXTRACTION_EMPTY` | 응답 content 없음 |
| `GROQ_EXTRACTION_INVALID_JSON` | 두 번째 응답까지 JSON 파싱 실패 |
| `GROQ_EXTRACTION_REFUSED` | 모델 refusal, 교정하지 않음 |
| `INVALID_NIGHTLY_EXTRACTION` | 두 번째 로컬 검증까지 실패 |

## 검증 결과

- lint, typecheck, 자동 테스트 115개 통과
- strict request, 빈 입력 skip, 1회 교정, 두 번째 실패, refusal, HTTP 실패 회귀 테스트
- prompt injection 문자열은 JSON 자료로 보존되고 system 규칙이 우선함을 테스트
- 비식별 합성 입력의 실제 Groq smoke 통과: 1회 호출, schema `1.0.0`, mood 1개, diary block 1개, safety none
- 실사용자 원문을 Groq로 보내는 smoke는 별도 외부 전송 승인을 받기 전까지 실행하지 않음
