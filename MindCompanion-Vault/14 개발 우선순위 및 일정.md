## 일정 기준

- 착수일: 2026-09-28
- 목표 출시일: 2026-11-20
- 구성: 1인 개발, 주 5개 개발일 기준
- 전체: 8주, 40개 개발일
- 순수 구현 32일 + 검증·수정·예비 8일
- 공휴일과 개인 일정은 포함하지 않았으며, 실제 휴무 발생 시 후순위 기능을 줄이고 출시 조건은 유지한다.

## 우선순위 원칙

1. **데이터 유실과 접근 통제를 먼저 막는다.** 대화가 저장되지 않거나 다른 사용자가 접근할 수 있으면 이후 기능은 의미가 없다.
2. **가장 짧은 사용자 가치 흐름을 먼저 완성한다.** `Telegram 대화 → 저장 → 일기 생성 → 전달`을 Dashboard보다 앞서 완성한다.
3. **LLM 출력은 기능보다 검증이 먼저다.** 근거 ID, schema, 멱등성 없이 추출 기능을 늘리지 않는다.
4. **기억은 수정·삭제가 가능할 때 출시한다.** 저장만 되고 잊을 수 없는 기억 기능은 활성화하지 않는다.
5. **Dashboard는 검증된 데이터를 읽는 화면으로 시작한다.** 복잡한 통계와 의미 검색은 후순위다.

## 일정 지연 시 축소 순서

출시일을 유지해야 할 경우 아래 순서로 범위를 줄인다.

1. 23:30 draft 일기 제외, 04:05 final만 유지
2. 기분·건강 차트를 단순 목록으로 대체

5. 모델 라우팅을 제외하고 단일 모델 유지

- 원문 선저장과 멱등성
