# 개발 로드맵

기간은 1인 개발 기준의 상대 추정치다. 일정일보다 각 단계의 종료 조건을 우선한다.

## 전체 순서

| 단계 | 예상 | 목표 | 선행 조건 |
|---|---:|---|---|
| M0 설계 확정 | 2~3일 | P0 결정, 계약, 환경 기준 확정 | 없음 |
| M1 대화 수직 슬라이스 | 4~6일 | Telegram ↔ LLM ↔ DB 한 경로 완성 | M0 |
| M2 야간 기록 파이프라인 | 5~7일 | 추출·근거·일기·전송 완성 | M1 |
| M3 장기 기억 | 4~6일 | 후보·확정·사용·삭제 완성 | M2 |
| M4 대시보드 | 7~10일 | 조회·검색·피드백·기억 관리 | M2, M3 일부 |
| M5 안정화·배포 | 5~7일 | 안전, 장애복구, 백업, 품질 검증 | M1~M4 |

총 27~39 개발일 범위이며 외부 서비스 설정과 품질 튜닝에 따라 달라질 수 있다.

## M0 — 설계 확정

- [[10 결정 기록]]의 P0 항목 확정
- 실행 언어와 패키지 구조 선택
- 환경변수 목록과 개발/운영 분리
- JSON Schema 및 DB migration 초안 정합화
- 비식별 테스트 대화 20~30개 준비

**종료 조건:** 아키텍처, 하루 마감, 기억 원본, 모델, 근거 관계가 문서와 스키마에서 한 가지 방식으로 일치한다.

## M1 — 대화 수직 슬라이스

- Telegram webhook과 허용 ID 검사
- 메시지 멱등 저장
- Groq provider와 타임아웃/재시도
- SOUL 규칙 기반 대화 프롬프트
- 관련 최근 메시지만 포함하는 컨텍스트
- 구조화 로그와 기본 상태 확인 endpoint

**종료 조건:** 중복 webhook, LLM 실패, Telegram 실패를 포함한 통합 테스트를 통과한다.

## M2 — 야간 기록 파이프라인

- 작업 실행 테이블과 상태 머신
- 하루 입력 snapshot과 input hash
- Structured Output 추출
- 근거 ID 서버 검증
- 일기 draft/final 및 버전 정책
- Telegram 발송 작업 분리
- 👍/👎 피드백 저장

**종료 조건:** 같은 날짜를 반복 실행해도 데이터가 오염되지 않고, 모든 일기 문장을 원문으로 점검할 수 있다.

## M3 — 장기 기억

- 기억 후보 생성 기준
- 사용자 확인이 필요한 기준
- 기억 원장과 변경 이력
- 대화 검색/주입 기준과 토큰 한도
- “잊어줘” 수정·삭제 경로
- Agent용 파일 투영 및 동기화 검증

**종료 조건:** 기억 추가, 갱신, 상충, 삭제 시나리오가 모두 재현 가능하다.

## M4 — 대시보드

- Supabase Auth 단일 계정
- 오늘/캘린더/일기/타임라인
- 키워드·날짜 검색
- 일기 근거 보기와 피드백
- 기억 관리
- 기본 기분/건강 추세

**종료 조건:** 브라우저에서 service role 없이 모든 사용자 기능을 수행하고 RLS 음성 테스트(비소유자 차단)를 통과한다.

## M5 — 안정화와 배포

- 위기 대응 문구와 연락처 배포 시점 재검증
- rate limit, timeout, circuit breaker
- 개인정보 마스킹 로그
- 백업 자동화와 복구 훈련
- 품질 골든셋 평가
- 배포·롤백 runbook
- 1~2주 제한 운영과 피드백 반영

**종료 조건:** [[11 실행 체크리스트]]의 출시 항목이 모두 완료되고 P0/P1 미해결 리스크가 없다.
