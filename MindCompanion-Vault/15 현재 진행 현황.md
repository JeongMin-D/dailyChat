## C02 DB 정합성 결과

- JSON Schema 모든 필드를 PostgreSQL 컬럼·관계·transient 값으로 분류했다.
- UTC 시각 `timestamptz`, local day `date`, confidence `numeric(5,4)`를 기준 타입으로 정했다.
- 원문과 파생 데이터는 유형별 연결 테이블과 복합 PK/FK로 연결한다.
- 원문 삭제는 영향 처리 전까지 restrict하고, 파생 부모 삭제 시 연결 행만 cascade한다.
- RLS 활성화, `anon`/`authenticated` 회수, `service_role` 명시 grant를 migration 공통 규칙으로 유지한다.
- C02 시점에는 운영 DB를 변경하지 않았고, C03에서 core domain과 근거 관계를 적용했다.

## C03 근거 스키마 결과

- `events`, `mood_entries`, `health_entries`, `diaries`, `diary_blocks`를 생성했다.
- event/mood/health/diary block 원문 근거와 diary block-event 근거 연결 테이블 5개를 생성했다.
- 모든 새 테이블에 RLS를 켜고 `anon`/`authenticated` 권한을 회수했으며 `service_role` CRUD만 명시했다.
- 복합 PK, FK, enum·범위·길이 CHECK와 cascade/restrict 삭제 정책을 실DB에서 확인했다.
- 정상 저장, 중복 근거 거부, 잘못된 confidence 거부, 참조 원문/event 삭제 거부를 임시 트랜잭션으로 검증하고 전부 롤백했다.
- Security Advisor의 정책 없음 INFO는 클라이언트 권한이 없는 server-only 단계의 의도된 상태이며 Dashboard 정책은 G01에서 추가한다.

## C04 작업과 알림 원장 결과

- `job_runs`에 재시도 예약 시각, 갱신 시각과 원자적 `claim_job_run`을 추가했다.
- `notification_outbox`는 `job_run_id`, `diary_id`와 전송 상태만 저장하고 원문·일기 본문을 복제하지 않는다.
- 작업과 알림은 due 상태와 5분 이상 멈춘 claim만 회수하며 attempt를 원자적으로 증가시킨다.
- outbox 멱등 키와 일기별 Telegram final unique 제약으로 중복 등록을 차단한다.
- 실DB에서 중복 claim, terminal timestamp, FK 삭제 보호, RLS·table/function 권한을 검증했다.
- 실제 Telegram 발송과 성공·실패 backoff 갱신은 D09 Worker 범위다.
