# ADR-002 — 하루 일기 확정 시점

## 상태

승인

## 배경

대화의 하루 경계는 KST 04:00인데 제안서의 23:30 일기 생성은 아직 끝나지 않은 같은 날의 입력을 누락할 수 있다. draft와 final을 동시에 운영하면 버전·알림·재실행 정책도 복잡해진다.

## 선택지

1. 매일 23:30에 일기 하나를 생성
2. 23:30 draft와 다음 날 04:05 final을 모두 생성
3. 다음 날 04:05에 전날 final만 생성

## 결정

MVP에서는 `Asia/Seoul` 기준 04:00에 local day를 닫고 04:05에 닫힌 전날의 final 일기만 생성한다. 하루 입력 구간은 `[당일 04:00, 다음 날 04:00)`이며 메시지의 서버 수신 시각으로 귀속한다. 스케줄러가 늦게 실행돼도 현재 시각이 아니라 처리 대상 local day를 명시한다.

23:30 draft와 미리보기 알림은 MVP에서 제외한다. 같은 날짜의 재실행과 늦게 도착한 입력 처리 방식은 ADR-007의 input hash·버전 정책으로 결정한다.

## 결과

- 장점: 닫힌 입력만 사용하므로 누락과 draft/final 중복을 줄이고 알림 흐름을 단순화한다.
- 단점: 사용자는 하루 기록을 다음 날 04:05 이후에 받으며 늦은 실행에 대한 운영 감시가 필요하다.
- 후속 작업: Worker가 대상 local day를 명시하고 04:05 실행, 30분 지연 알림, 경계값 테스트를 구현한다.

## 검증 방법

- KST 03:59:59와 04:00:00 메시지가 서로 다른 local day에 귀속되는지 테스트한다.
- DST가 있는 다른 설정 시간대에서도 같은 현지 경계 규칙이 유지되는지 테스트한다.
- 04:05 작업을 반복해도 같은 입력으로 final이 중복 생성되지 않는지 확인한다.
