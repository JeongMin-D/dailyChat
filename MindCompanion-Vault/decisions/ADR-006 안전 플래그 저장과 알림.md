# ADR-006 — 안전 플래그 저장과 알림

## 상태

승인

## 배경

건강·위기 표현은 일반 일기 생성과 같은 방식으로 상세 재현하거나 운영 로그에 남기면 안 된다. 반대로 모델 출력에만 일시적으로 표시하면 발송 분기와 사후 검증을 재현할 수 없다.

## 선택지

1. 안전 플래그를 저장하지 않고 응답 시점에만 사용
2. 원문 인용과 자유 형식 판단을 함께 저장
3. 제한된 등급·사유 코드·근거 ID만 접근 제한 메타데이터로 저장

## 결정

안전 판정은 `none`, `concern`, `urgent` 등급과 허용된 사유 코드, 판정 시각, 검사기 버전, source ID만 저장한다. 원문 인용, 진단명, 자유 형식 모델 추론은 안전 메타데이터에 저장하지 않는다. 모델의 판정은 신뢰하지 않고 schema·source ID·enum을 서버에서 검증한다.

`none`은 정상 일기 발송, `concern`은 단정적 표현을 제거한 안전한 일기 발송, `urgent`는 일반 일기 자동 발송을 보류하고 검증된 안전 안내 흐름으로 분기한다. 시스템은 의료 진단·처방을 하거나 제3자·응급기관에 자동 신고하지 않는다. 운영 알림에는 등급, run ID, 오류 코드만 포함하고 원문·일기·건강 내용을 넣지 않는다.

안전 메타데이터는 Bot/Worker 서버 역할만 쓰고 전용 소유자 RLS가 준비되기 전에는 Dashboard에 노출하지 않는다.

## 결과

- 장점: 개인정보 노출을 줄이면서 발송 분기와 판정 재현성을 유지한다.
- 단점: 오탐과 미탐 가능성이 남고 안전 문구와 연락처의 지속적인 검증이 필요하다.
- 후속 작업: C01 enum, C05 저장 필드, D10 발송 분기, G04 회귀 테스트와 출시 시점 연락처 재검증을 구현한다.

## 검증 방법

- 정상·우려·긴급 fixture에서 등급과 발송 분기가 기대대로 동작하는지 테스트한다.
- 잘못된 등급, 다른 날짜 source ID, 자유 형식 원문 저장을 거부하는지 확인한다.
- 로그와 운영 알림에 사용자 원문·건강 내용이 포함되지 않는지 검사한다.
