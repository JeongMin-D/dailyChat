# ADR-008 기억 후보 승인

## 결정

- 비건강 후보의 confidence가 0.8 이상이면 자동 확정한다.
- confidence가 0.8 미만이거나 category가 health이면 Telegram 확인을 필수화한다.
- 확인과 거절은 UUID callback 버튼으로 받고 설정된 user/chat ID를 DB에서 다시 검증한다.
- 동일 결정은 멱등 no-op, 반대 결정은 conflict로 두며 수정·상충 처리는 E05에서 구현한다.

## 이유

모든 후보를 묻는 알림 피로를 줄이면서 민감 정보와 불확실한 추론은 사용자가 통제할 수 있어야 한다. 텍스트 답장 해석 대신 제한된 callback data를 사용하면 오판과 프롬프트 개입 없이 결정을 연결할 수 있다.

## 결과

확정 상태만 E04 대화 Context 후보가 된다. 건강 후보는 확신도가 높아도 자동 사용하지 않는다.
