# ADR-005 — 서버 런타임

## 상태

승인

## 배경

제안서의 예시는 Python이지만 현재 개발 환경에는 Python이 없고 Node.js 24와 npm 11이 준비돼 있다. Bot, 야간 Worker, Dashboard, JSON Schema 사이의 타입과 런타임을 가능한 한 단순하게 유지할 필요가 있다.

## 선택지

1. Python Bot/Worker + TypeScript Dashboard
2. Node.js Bot/Worker + TypeScript Dashboard
3. OpenClaw 설정만 사용하고 별도 서버 코드를 최소화

## 결정

Node.js 24를 서버 런타임으로 사용한다. 초기 코어 로직은 외부 의존성이 없는 ESM JavaScript와 JSDoc으로 시작하고, Next.js 도입 시 공유 계약과 애플리케이션 코드를 TypeScript로 점진 전환한다. OpenClaw는 대화 정책과 Agent 기능의 adapter로 두며, 데이터 원장과 멱등 처리는 애플리케이션과 Supabase가 담당한다.

## 결과

- 장점: 현재 환경에서 즉시 테스트 가능하며 Bot·Worker·Web 간 코드와 계약을 공유하기 쉽다.
- 단점: 제안서의 Python 예시를 그대로 사용할 수 없고 초기 JS에서 TypeScript 전환 비용이 생긴다.
- 후속 작업: Telegram adapter와 Groq provider를 Node.js 모듈로 구현하고 공유 JSON Schema를 추가한다.

## 검증 방법

- 루트 `npm test`가 모든 workspace의 순수 로직 테스트를 실행한다.
- Bot과 Worker가 같은 local day 및 contract 구현을 사용한다.
