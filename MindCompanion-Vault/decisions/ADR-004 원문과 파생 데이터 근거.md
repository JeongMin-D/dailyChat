# ADR-004 — 원문과 파생 데이터 근거

## 상태

승인

## 배경

하나의 사건·기분·건강 기록은 여러 메시지에서 추출될 수 있고 하나의 메시지가 여러 파생 기록의 근거가 될 수 있다. 단일 `message_id`나 검증되지 않은 JSON source 배열만으로는 복수 근거, 삭제 영향, 일기 문장 추적을 안정적으로 표현할 수 없다.

## 선택지

1. 파생 레코드마다 단일 `message_id` 저장
2. source ID 배열을 파생 레코드의 JSON에 저장
3. 파생 유형별 외래 키 연결 테이블로 다대다 관계 저장

## 결정

원문과 파생 데이터의 근거는 유형별 연결 테이블로 저장한다. 최소 범위는 `event_message_sources`, `mood_message_sources`, `health_message_sources`이며 일기는 순서가 있는 근거 단위로 생성해 각 단위가 message 또는 event 근거를 하나 이상 갖게 한다. 기억 후보도 같은 원칙으로 원문 또는 검증된 파생 레코드에 연결한다.

LLM이 반환하는 source ID 배열은 입력 계약일 뿐 원장이 아니다. 서버는 저장 전에 모든 ID가 해당 소유자와 처리 대상 local day의 입력 snapshot에 포함되는지 검증한다. 연결 쌍에는 unique 제약과 실제 foreign key를 사용하며 검증 실패 시 파생 레코드를 부분 저장하지 않는다.

## 결과

- 장점: 복수 원문 근거, 삭제 영향 분석, 일기 문장별 설명 가능성, 잘못된 교차 사용자 연결 차단이 가능하다.
- 단점: 테이블과 join 수가 늘고 일기 본문을 근거 단위로 구성해야 한다.
- 후속 작업: C01 JSON Schema와 C03 migration에서 근거 단위·연결 테이블·unique/FK 제약을 함께 정의한다.

## 검증 방법

- 복수 source ID가 손실 없이 저장되고 중복 연결이 생기지 않는지 contract/integration test로 확인한다.
- 다른 사용자, 다른 local day, 존재하지 않는 ID를 거부하는지 테스트한다.
- 표본 final 일기의 모든 생성 단위를 원문까지 역추적할 수 있는지 확인한다.
