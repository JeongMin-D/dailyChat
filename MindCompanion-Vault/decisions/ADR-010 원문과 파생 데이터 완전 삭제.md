# ADR-010 — 원문과 파생 데이터 완전 삭제

## 상태

승인

## 배경

원문만 삭제하면 FK가 거부하고, 연결만 제거하면 일기·기억·건강 자료에 삭제 대상 내용이 남을 수 있다. 반대로 파생 자료를 stale 상태로 보존하면 완전 삭제 요구와 충돌한다.

## 선택지

1. 원문만 삭제하고 파생 자료는 유지한다.
2. 파생 자료를 stale로 남겨 나중에 재생성한다.
3. 닫힌 날짜의 파생 자료와 원문을 한 트랜잭션에서 함께 삭제한다.

## 결정

3번을 채택한다. 서비스의 하루 경계와 일기 생성 단위가 날짜이므로 MVP의 완전 삭제 단위도 닫힌 local day로 고정한다. 교차 날짜 근거는 자동 추측하지 않고 삭제를 중단한다.

## 결과

- 장점: 원문이 일기·기억에 남지 않고 FK 순서와 rollback을 DB가 보장한다.
- 단점: 메시지 한 건만 골라 삭제할 수 없고, 열린 오늘은 즉시 삭제할 수 없다.
- 후속 작업: 삭제 후 투영 재생성 회귀 테스트, Dashboard 확인 UI, 백업 교체를 연결한다.

## 검증 방법

- 합성 원문과 모든 파생 종류를 만든 뒤 RPC 결과와 삭제 건수를 확인하고 rollback한다.
- 잘못된 확인 문자열, 비소유자, 열린 날짜, running/sending 상태를 거부한다.
- `anon`·`authenticated` 실행 권한이 없고 service role만 실행 가능한지 확인한다.
- 삭제 후 일기·기억·투영에서 대상 내용이 다시 나타나지 않는지 검증한다.
