# ADR-001 — MVP LLM 공급자

## 상태

승인

## 배경

제안서에는 Groq GPT-OSS와 Claude 예시가 함께 있어 실시간 대화와 야간 작업의 공급자, 실패 처리, 품질 기준이 갈릴 수 있다. MVP에서는 공급자 전환보다 한 경로의 품질과 운영 특성을 먼저 검증해야 한다.

## 선택지

1. Groq로 모든 MVP LLM 작업 통일
2. 실시간 대화는 Groq, 야간 작업은 다른 공급자 사용
3. 요청마다 여러 공급자를 자동 라우팅

## 결정

MVP의 실시간 대화, 구조화 추출, 일기 생성은 Groq provider 하나를 사용한다. 모델명은 작업별 환경변수로 분리하며 기본값은 검증된 `openai/gpt-oss-120b`로 둔다. 애플리케이션은 provider 인터페이스를 유지하되 자동 fallback과 다중 공급자 라우팅은 구현하지 않는다.

모델 또는 프롬프트가 바뀌면 `provider`, `model`, `prompt_version`을 결과와 작업 실행에 기록하고 고정 골든셋을 통과한 뒤 배포한다. 로그에는 사용자 원문과 모델 응답 본문을 넣지 않는다.

## 결과

- 장점: 오류·재시도·비용·품질 관측 경로가 하나라 M2 구현과 장애 분석이 단순하다.
- 단점: Groq 장애나 모델 품질 저하 시 자동 대체가 없으며 공급자 종속이 생긴다.
- 후속 작업: C01 계약에 model/prompt version을 포함하고, 평가 결과가 쌓인 뒤 ADR-011에서 작업별 모델 분리를 다시 검토한다.

## 검증 방법

- 실제 연결 smoke test로 설정한 모델의 사용 가능 여부를 확인한다.
- 대화와 야간 작업 테스트에서 provider/model/prompt version이 기록되는지 확인한다.
- 모델 변경 전후 동일 골든셋의 추출 정확도와 일기 근거성을 비교한다.
