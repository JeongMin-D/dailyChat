# 안전 알림 분기

## 정책

승인된 [[decisions/ADR-006 안전 플래그 저장과 알림]]에 따라 다음처럼 처리한다.

| level | notification type | 처리 |
|---|---|---|
| `none` | `daily_diary` | 일반 일기 발송 |
| `concern` | `daily_diary` | 지지 문구를 붙인 안전한 일기 발송 |
| `urgent` | `safety_guidance` | 일반 일기 보류, 고정 안전 안내만 발송 |

자동 신고, 응급기관 호출, 제3자 운영 알림은 하지 않는다.

## 이중 보호

등록 RPC는 `safety_assessments`를 조회해 notification type을 결정한다. claim RPC도 조합을 다시 확인하므로 urgent job에 수동으로 잘못 만든 `daily_diary` outbox는 claim되지 않는다.

urgent claim 결과에는 다음 값이 없다.

- diary title
- diary block과 일기 본문
- safety reason code
- source message와 원문 인용

Worker formatter도 `notificationType=safety_guidance`와 `safetyLevel=urgent` 조합만 받고 입력 payload를 보간하지 않은 고정 문구만 반환한다.

## 안전 안내

고정 안내는 현재 안전 여부를 묻고, 즉시 자신이나 타인을 해칠 위험이 있으면 혼자 있지 말고 가까운 사람에게 알린 뒤 112 또는 119에 연락하도록 안내한다. 24시간 지원 번호는 다음과 같다.

- 자살예방 상담전화 `109`
- 정신건강 위기상담전화 `1577-0199`

2026-09-25 보건복지부와 국가정신건강정보포털 공식 안내에서 다시 확인했다. 문구에는 진단이나 자동 신고가 아니라는 점과 urgent 일기를 자동 발송하지 않았다는 점을 명시한다.

## 검증

- 운영 migration `d10_safety_notification_routing` 적용
- none → daily diary + title/block 1개
- concern → daily diary + title/block 1개
- urgent → safety guidance + title null + block 0개
- urgent payload에 합성 일기 문구가 포함되지 않음
- 잘못 만든 urgent daily diary claim은 null, 상태 pending 유지
- 모든 합성 데이터 rollback 후 잔존 0건
- RPC invoker·빈 search path·service-role 전용과 Data API 도달 확인
- 자동 테스트 152개 통과
