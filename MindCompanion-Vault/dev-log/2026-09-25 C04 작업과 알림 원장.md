# C04 작업과 알림 원장

## 시작 전 확인

- `main`과 `origin/main`은 C03 완료 커밋에서 동기화되어 있었다.
- 사용자 변경은 `MindCompanion-Vault/.obsidian/workspace.json`뿐이며 수정·커밋에서 제외했다.
- 기존 job_runs, C03 diaries FK, 운영 상태 문서와 백로그 C04/C05 경계를 대조했다.
- C04는 운영 claim/outbox, C05는 safety와 model/prompt/schema 재현 metadata로 범위를 유지했다.
- Supabase Data API 권한 변경과 queue 보안 지침을 다시 확인했다.

## 구현

- 공유 job/notification 상태와 transition 계약 추가
- job_runs에 `available_at`, `updated_at`, 길이·terminal 시각 CHECK 추가
- due 또는 5분 stale 작업을 가져오는 `claim_job_run`
- reference-only `notification_outbox` 추가
- outbox 멱등 키, 일기별 알림 unique, 상태·attempt·시각 CHECK
- due 또는 5분 stale 알림을 가져오는 `claim_notification`
- claim 후보와 FK 조회 인덱스
- RLS, client 역할 권한 회수, service_role table/function 권한
- 계약 테스트 3개와 migration 테스트 5개 추가

## 적용과 실DB 검증

- transaction dry-run 성공 후 `c04_job_runs_notification_outbox` migration 적용
- Supabase migration history의 다섯 번째 migration 확인
- job과 notification 첫 claim 성공, 활성 중복 claim 실패
- 5분 stale 회수와 attempt 2 증가 확인
- terminal/sent 완료 시각 CHECK 확인
- outbox 중복 등록과 참조 일기 삭제 거부 확인
- outbox에 content/payload/diary text 컬럼이 없음을 카탈로그에서 확인
- 검증 데이터 전체 rollback 및 잔여 0건 확인

## Advisor 결과

- Security: 기존과 동일한 RLS 정책 없음 INFO만 존재한다. client 권한이 없는 server-only 단계라 의도된 상태다.
- Performance: 신규 claim/FK 인덱스 미사용 INFO가 추가됐다. D09 실제 조회 후 사용 통계를 재검토한다.
- ERROR/WARN 등급의 신규 보안·성능 문제는 없다.

## 검증

- `npm run check`: lint·typecheck·자동 테스트 78개 통과
- 실DB 상태 전이·멱등·권한·FK·rollback 확인
- 비밀값과 사용자 원문·일기 본문을 새 코드·문서·outbox에 포함하지 않음
