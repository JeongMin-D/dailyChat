# E02 기억 후보 추출

- nightly 계약을 `schemaVersion 1.1.0`, prompt `nightly-v2`, pipeline `nightly-pipeline-v2`로 올렸다.
- `memoryCandidates`에 분류, 사실, 확신도, 당일 시작 유효기간과 직접 원문 근거를 추가했다.
- 여러 날 유지할 사용자 정보·선호·관계·프로젝트·결정·생활 패턴만 후보로 만들고 일회성 일정·감정·잡담·추측은 제외한다.
- 민감한 건강 정보는 사용자가 직접 말한 사실만 후보로 허용하고 진단·확대 해석을 금지했다.
- 후보별 근거 중복, snapshot 밖 ID, 같은 분류·사실 중복, 당일이 아닌 시작일과 종료일 설정을 로컬 의미 검증에서 거부한다.
- 운영 Supabase RPC가 기존 nightly 결과와 기억 후보·원문 근거를 한 트랜잭션에 저장하도록 교체했다.
- 운영 DB rollback 검증에서 후보 1건·근거 1건·일기와 job 성공 전환을 함께 확인했고 합성 데이터는 남기지 않았다.
- 실제 Groq 합성 smoke에서 지속 선호가 후보 1건으로 추출됐고 외부 DB·Telegram 쓰기는 없었다.
- Security Advisor의 no-policy INFO는 server-only 모델에서 의도된 상태이며 새 오류는 없다.
