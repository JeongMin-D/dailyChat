# C03 근거 스키마

## 시작 전 확인

- `main`과 `origin/main`은 C02 완료 커밋에서 동기화되어 있었다.
- 사용자 변경은 `MindCompanion-Vault/.obsidian/workspace.json`뿐이며 이번 작업에서 제외했다.
- C02 실행 계약, JSON Schema, ADR-004, 기존 migration 3개와 실DB 상태를 먼저 대조했다.
- Supabase 최신 Data API 권한 변경과 RLS 문서를 다시 확인했다.
- 로컬 Supabase CLI는 설치되어 있지 않아 저장소의 기존 `database/migrations/000N_*.sql` 규칙으로 파일을 작성하고 MCP migration으로 적용했다.

## 구현

- `0004_core_domain_sources.sql` 추가
- core domain: events, mood_entries, health_entries, diaries, diary_blocks
- provenance: event/mood/health/diary block-message, diary block-event 연결 테이블
- domain → job run은 restrict, 파생 부모 → 연결 행은 cascade, source message/event 삭제는 restrict
- enum, confidence, mood/severity, 문자열 길이, 배열 수, day/version·block position unique 제약
- 날짜·job run·역방향 근거 조회 인덱스
- 모든 새 테이블 RLS와 server-only 명시 권한
- migration SQL의 테이블·RLS·권한·FK·범위를 검사하는 자동 테스트 5개

## 적용과 실DB 검증

- `BEGIN ... ROLLBACK` dry-run 성공 후 `c03_core_domain_sources` migration 적용
- Supabase migration history에 네 번째 migration 등록 확인
- 새 테이블 10개 전부 RLS 활성화 확인
- `anon`/`authenticated` CRUD false, `service_role` CRUD true 확인
- 모든 FK의 cascade/restrict 동작을 카탈로그에서 확인
- 정상 도메인·근거 저장 성공
- 중복 근거, confidence 1 초과, 참조 원문 삭제, 참조 event 삭제 거부 확인
- 검증 데이터 전체 rollback 및 잔여 0건 확인

## Advisor 결과

- Security: RLS 정책 없음 INFO만 존재한다. client 역할의 table 권한을 회수한 server-only 단계라 의도된 상태다.
- Performance: 적용 직후 인덱스 미사용 INFO만 존재한다. D05 저장·조회 경로 구현 뒤 실제 사용 통계로 재검토한다.
- ERROR/WARN 등급의 신규 보안·성능 문제는 확인되지 않았다.

## 검증

- `npm run check`: lint·typecheck·자동 테스트 70개 통과
- migration dry-run과 적용 성공
- 실DB 제약·권한·RLS·rollback 확인
- 비밀값과 사용자 원문을 코드·문서·테스트 데이터에 포함하지 않음
