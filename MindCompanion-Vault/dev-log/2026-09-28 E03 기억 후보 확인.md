# E03 기억 후보 확인

## 구현

- 비건강 confidence 0.8 이상 후보를 자동 확정하고 낮은 확신·건강 후보는 pending으로 유지한다.
- 후보별 참조 전용 `memory_confirmation_outbox`와 claim·완료·실패 재시도 RPC를 추가했다.
- Telegram 인라인 확인/거절 버튼, callback query 응답과 버튼 제거를 webhook 흐름에 연결했다.
- owner user/chat ID를 DB에서 재검증하고 동일 결정 no-op·반대 결정 conflict를 적용했다.
- urgent safety 경로에서는 기억 후보 알림을 보내지 않는다.

## 검증

- lint, typecheck, 자동 테스트 193개 통과
- 운영 Supabase migration 적용
- 실제 DB rollback 검증에서 자동 확정, 건강·낮은 확신 pending, outbox 2건, claim, 확인·거절·중복·충돌 상태 전이를 확인했다.
- rollback 뒤 합성 후보·outbox 잔존 0건을 확인했다.
- 새 테이블 RLS, 함수 `SECURITY INVOKER`, 빈 search path, service-role 전용 권한을 확인했다.
- Security Advisor의 정책 없음 INFO는 기존 server-only 모델과 동일하며 새 ERROR/WARN은 없다.
