# C02 DB 정합성

## 시작 전 확인

- `main`과 `origin/main`은 최근 완료 커밋 기준으로 동기화되어 있었다.
- 사용자 변경은 `MindCompanion-Vault/.obsidian/workspace.json` 한 건이었다.
- Obsidian 화면 배치 상태로 판단해 수정·검증·커밋 대상에서 제외했다.
- 기존 JSON Schema, foundation migration, ADR-004·006을 다시 대조했다.

## 구현

- `nightlyDatabaseContract`에 모든 야간 추출 필드의 저장 위치와 PostgreSQL 타입을 선언했다.
- 컬럼, collection, relation, transient, 조건부 저장을 구분했다.
- enum, 수치 범위, nullable, 길이, 배열 한도를 JSON Schema와 맞췄다.
- 유형별 source 연결 테이블, 복합 PK, FK 삭제 정책을 확정했다.
- RLS와 역할별 명시 권한을 target 계약에 포함했다.
- JSON Schema와 DB 계약이 어긋나면 실패하는 자동 테스트 5개를 추가했다.

## 핵심 결정

- `eventRef`는 저장하지 않고 한 저장 트랜잭션의 event ID 해석에만 사용한다.
- 시간은 `timestamptz`, local day는 `date`, confidence는 `numeric(5,4)`다.
- `sourceMessageIds`는 JSON/text array가 아니라 유형별 FK 연결 테이블로 저장한다.
- 파생 부모 삭제 시 연결 행은 cascade하지만 원문 삭제는 restrict한다.
- source snapshot 소속, 최소 근거 수, 배열 중복 같은 교차 규칙은 저장 전 검증과 원자적 트랜잭션으로 강제한다.
- safety `none`은 저장하지 않고 `concern|urgent`만 제한 메타데이터로 저장한다.

## Supabase 최신 기준 반영

- 새 `public` 테이블의 Data API 자동 노출 여부에 의존하지 않는다.
- 각 migration에서 RLS를 활성화하고 역할 권한을 명시한다.
- `anon`과 `authenticated` 권한은 회수하고 서버의 `service_role`에 필요한 CRUD만 grant한다.
- C02는 설계·검토 단계이므로 운영 DB DDL은 실행하지 않았다.

## 검증

- 계약 패키지 테스트 16개 통과
- 전체 `npm run check`로 lint·typecheck·자동 테스트 확인
- Supabase 카탈로그를 읽기 전용으로 조회해 파생 테이블이 아직 적용되지 않았음을 확인
- 비밀값과 사용자 원문을 새 코드·문서·Git diff에 포함하지 않음
