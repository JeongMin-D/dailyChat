## 근거와 정합성 확인

- 기존 제안서 충돌 목록, 시스템 아키텍처, 데이터 흐름, 보안·운영 원칙과 현재 M1 구현을 대조했다.
- 실제 환경의 `APP_TIMEZONE`, `DAY_BOUNDARY_HOUR`, `DIARY_FINAL_TIME`, Groq 모델 설정과 결정이 일치한다.
- Supabase 최신 문서에서 Data API 접근은 grant와 RLS 두 계층으로 관리해야 함을 확인했다.
- 2026-04-28 changelog의 Data API 자동 노출 기본값 변경을 반영해 migration에서 권한을 명시하도록 결정했다.
- 이번 작업은 문서 결정만 변경했으며 DB schema와 운영 데이터를 변경하지 않았다.

- `npm run check`: lint·typecheck·자동 테스트 49개 통과

- 문서 diff 비밀값·공백 오류 검사 통과

## Supabase 보안 반영

- server secret/service role은 Bot·Worker 서버에만 둔다.
- Dashboard는 publishable key, 사용자 세션, 소유자 RLS를 사용한다.
- 공개 스키마의 객체 접근은 자동 기본값에 기대지 않고 grant와 RLS를 migration에서 함께 관리한다.
- 투영 충돌과 삭제 처리에서 Supabase 기억 원장이 항상 우선한다.
