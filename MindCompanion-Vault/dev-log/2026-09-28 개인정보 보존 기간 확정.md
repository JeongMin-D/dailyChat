# 개인정보 보존 기간 확정

## 확인

- 기존 사용자 변경은 `.obsidian/workspace.json` 한 건이며 작업에서 제외했다.
- 운영 Supabase 프로젝트는 Free 플랜·정상 상태이며 원문 12건, 일기 1건, 건강·기억 0건이다.
- Supabase 공식 문서상 관리형 일일 백업은 Pro 이상이며 Free 플랜은 CLI 논리 export와 외부 보관이 권장된다.
- 2026-09-28 Supabase breaking changes 중 이번 문서 결정에 영향을 주는 백업 API 변경은 없었다.

## 결정

- ADR-012로 핵심 기록은 사용자 완전 삭제까지, 후보·운영 원장·로그·백업은 30~90일 상한으로 확정했다.
- 개인정보 dump는 저장소와 GitHub Actions artifact에 두지 않는다.
- 완전 삭제 뒤 삭제 전 자체 백업을 폐기하고 삭제 후 새 백업을 만든다.

## 다음 작업

- 원문 삭제를 막는 현재 FK를 따라 파생 데이터 영향 처리 순서를 구현한다.
- 삭제된 내용이 일기·기억·투영에서 재등장하지 않는 회귀 테스트를 추가한다.
