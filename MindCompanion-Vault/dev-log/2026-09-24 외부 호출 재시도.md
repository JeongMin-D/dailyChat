## 구현

- Groq와 Telegram에 공통 `fetchWithRetry` 적용
- 429 및 5xx만 HTTP 재시도, 인증·권한 등 다른 4xx는 즉시 실패
- 네트워크 오류와 timeout 재시도
- bounded exponential backoff와 equal jitter
- 표준 `Retry-After` 헤더 및 Telegram JSON `parameters.retry_after` 처리
- 기본 총 3회 시도, 250ms 시작, 최대 2초 지연
- `upstream_retry_scheduled` 구조화 경고 로그 추가
- 환경변수로 시도 횟수와 지연 범위 조정 가능
