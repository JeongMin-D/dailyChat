# C05 안전과 재현 메타데이터

## 시작 전 확인

- `main`과 `origin/main`은 C04 완료 커밋에서 동기화되어 있었다.
- 사용자 변경은 `MindCompanion-Vault/.obsidian/workspace.json`뿐이며 작업에서 제외했다.
- ADR-001·006, JSON safety 계약, C02 DB mapping과 실DB job_runs 상태를 대조했다.
- job_runs는 0건이고 safety 테이블이 없음을 적용 전에 확인했다.
- Supabase Data API explicit grant와 RLS 보안 문서를 다시 확인했다.

## 구현

- job run 재현 계약과 SHA-256 input hash 형식 추가
- job_runs에 provider/model/prompt/schema version 추가
- nightly run에서 day·input hash·모든 version 필드 필수화
- `concern|urgent` 전용 `safety_assessments` 추가
- 제한 reason code, checker version, assessed timestamp 제약
- `safety_message_sources` 복합 PK와 FK 삭제 정책
- safety 테이블 RLS와 server-only 명시 권한
- 공유 계약 테스트 3개와 migration 테스트 5개 추가

## 적용과 실DB 검증

- transaction dry-run 성공 후 `c05_safety_reproducibility` migration 적용
- Supabase migration history의 여섯 번째 migration 확인
- 정상 nightly run과 concern assessment/source 저장 성공
- 재현 필드 누락과 uppercase hash 거부
- none level, 미허용·빈 reason code 거부
- run별 중복 assessment와 중복 source 거부
- 참조 원문 삭제 거부
- safety 컬럼이 제한 metadata 8개뿐임을 카탈로그로 확인
- 검증 데이터 전체 rollback 및 잔여 0건 확인

## Advisor 결과

- Security: 기존과 같은 RLS 정책 없음 INFO만 있다. client table 권한이 없는 server-only 단계라 의도된 상태다.
- Performance: 신규 safety 조회 인덱스 미사용 INFO가 있다. 실제 D10 분기 구현 후 재검토한다.
- ERROR/WARN 등급의 신규 보안·성능 문제는 없다.
