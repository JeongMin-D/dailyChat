## 새 작업 처리 원칙

1. 작업 전 Git 상태와 최근 커밋을 확인한다.
2. 사용자가 진행한 변경이 있으면 새 작업보다 먼저 관련성을 판단한다.
3. 관련 변경이면 diff, 테스트, 외부 설정을 검증해 실제 이행 여부를 확인한다.
4. 실패하거나 충돌하면 다음 구현을 진행하지 않고 원인과 선택지를 보고한다.
5. 관련 없는 사용자 변경은 수정·되돌림·커밋하지 않는다.
6. 작업 완료 후 진행 현황, 백로그, 개발 일지를 함께 갱신한다.
