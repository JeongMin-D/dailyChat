# E04 활성 기억 Context

## 구현

- 대화 생성 직전에 `memory_candidates`에서 `confirmed` 상태이면서 처리일에 유효한 최신 기억을 최대 8개 조회한다.
- 기억과 최근 대화는 기존 `CONVERSATION_CONTEXT_CHARS` 6,000자 예산을 공유한다.
- 기억은 별도 system 메시지의 참고 자료로 표시하고 내부 문장을 실행 지시로 취급하지 않도록 고정했다.
- pending·rejected·미래 시작·만료 기억은 Data API 필터에서 제외한다.

## 검증

- `npm run check`: lint, typecheck, 자동 테스트 196개 통과
- 운영 Supabase SQL 상태 집계와 실제 Data API 조회 결과 활성 기억 0건 일치
- 운영 데이터 변경과 Telegram·Groq 호출 없음
- 신규 migration이나 환경변수는 필요하지 않음
